LIFE HUB - INSTALLAZIONE E DEPLOY IN PRODUZIONE
================================================

Questa procedura installa Life Hub su un database vuoto. Non esistono script
di migrazione o importazione da applicazioni precedenti.


1. REQUISITI
------------

- PHP 7.4.33 con fileinfo, json, mbstring, openssl, PDO, pdo_mysql e session.
- MySQL compatibile con MySQL 5.0 e tabelle MyISAM.
- Apache con mod_rewrite e supporto ai file .htaccess.
- Node.js/npm e Composer sulla macchina usata per la build.
- Directory pubblica di destinazione: /umbertini.
- Directory applicativa per gli upload: /umbertini/uploads.


2. CONFIGURAZIONE
-----------------

Copiare:

  api/config/app.example.php

in un percorso protetto fuori dal repository, per esempio:

  C:\secure\lifehub.production.php

Compilare almeno:

- environment = production
- apiBasePath = /umbertini/api
- siteName
- dbHost, dbPort, dbName, dbUser, dbPass
- sessionName
- sessionIdleSeconds
- storagePath
- logPath

Configurazione consigliata per lo storage:

  $applicationRoot = dirname(__DIR__);
  $privateRuntime = $applicationRoot . DIRECTORY_SEPARATOR . 'uploads';

  'storagePath' => $privateRuntime,
  'logPath' => $privateRuntime
      . DIRECTORY_SEPARATOR . 'logs'
      . DIRECTORY_SEPARATOR . 'application.log',

Validare il file:

  .\tools\php7433.ps1 .\api\bin\lifehub config:check `
    C:\secure\lifehub.production.php


3. DATABASE VUOTO
-----------------

Creare un database dedicato con charset UTF-8 e un utente con i privilegi
necessari sulle sole tabelle dell'applicazione.

Non applicare lo schema a un database esistente. Il comando rifiuta un target
che contiene già tabelle con prefisso lh_.

Verifica:

  .\tools\php7433.ps1 .\api\bin\lifehub db:init:dry-run `
    C:\secure\lifehub.production.php

Inizializzazione:

  .\tools\php7433.ps1 .\api\bin\lifehub db:init `
    C:\secure\lifehub.production.php

Creazione del primo amministratore:

  .\tools\php7433.ps1 .\api\bin\lifehub admin:create `
    C:\secure\lifehub.production.php `
    "Amministratore" `
    "PASSWORD-DI-ALMENO-12-CARATTERI" `
    "Famiglia" `
    "Europe/Rome"

Il comando crea anche il nucleo familiare e la lista della spesa primaria.
Rimuovere la password dalla cronologia del terminale e cambiarla dopo il primo
accesso.

Controlli:

  .\tools\php7433.ps1 .\api\bin\lifehub db:inspect `
    C:\secure\lifehub.production.php

  .\tools\php7433.ps1 .\api\bin\lifehub integrity `
    C:\secure\lifehub.production.php


4. GATE E BUILD
---------------

Dalla directory principale del repository:

  .\ops\release-readiness.ps1 -WithDatabaseIntegration

Generare il pacchetto:

  .\ops\build-release.ps1 `
    -ConfigurationFile C:\secure\lifehub.production.php

Il risultato è:

  .release\umbertini

La build incorpora una copia protetta della configurazione e non include
credenziali sorgenti, database, upload o log.


5. PUBBLICAZIONE
----------------

1. Eseguire un backup dell'eventuale installazione corrente.
2. Caricare il contenuto di .release\umbertini nella directory /umbertini.
3. Verificare che Apache legga /umbertini/.htaccess.
4. Creare, se mancanti:

     /umbertini/uploads/files
     /umbertini/uploads/logs

5. Applicare a entrambe le directory il file deploy/storage.htaccess.
6. Concedere all'utente PHP scrittura soltanto su uploads/files e uploads/logs.
7. Negare accesso HTTP diretto a config, src, vendor e uploads privati.

Non copiare nella directory pubblica file .env, backup SQL, archivi ZIP,
credenziali o configurazioni sorgenti.


6. SMOKE TEST
-------------

Verificare:

- GET /umbertini/ restituisce la PWA.
- GET /umbertini/manifest.webmanifest restituisce il MIME corretto.
- GET /umbertini/api/v1/auth/session restituisce JSON.
- /umbertini/config/app.php non è scaricabile.
- /umbertini/uploads/files non è navigabile né scaricabile direttamente.
- login del primo amministratore.
- apertura di Attività, Spesa, Ricette e Admin.
- caricamento e successivo download autenticato di un file di prova.
- installazione PWA e icone su desktop e dispositivo mobile.


7. BACKUP
---------

Prima di ogni aggiornamento applicativo salvare separatamente:

- dump completo del database;
- directory /umbertini/uploads;
- configurazione applicativa;
- pacchetto applicativo precedentemente pubblicato.

Gli script ops/backup-database.ps1, ops/backup-uploads.ps1 e
ops/restore-isolated.ps1 possono essere usati per verificare backup e ripristino
su destinazioni isolate.
